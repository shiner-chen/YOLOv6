## ✅ 过滤影响预测

### 使用80px阈值

```
总图片数:    5000张 (假设)
过滤图片:    ~50-100张 (1-2%)
保留图片:    ~4900-4950张 (98-99%)
```

### 结论

**影响极小！只会损失1-2%的图片。**

这些被过滤的图片主要是：
- 近距离拍摄（不符合实际应用场景）
- ROI切片时选择了过近的目标
- 数据采集异常case

---

## ⚠️ 异常情况判断

### 如果实际过滤率 >5%

说明数据集可能混入了：

1. **非Motion-guided数据**
   - 随机裁剪的ROI
   - 固定位置截取
   - 全图下采样

2. **多样性数据集**
   - 近距离拍摄的无人机
   - 手动标注的训练数据
   - 合成/增强数据

3. **ROI切片策略问题**
   - 选择了过近的距离
   - Blob检测阈值设置不当
   - 没有距离筛选机制

### 处理建议

| 过滤率 | 判断 | 建议 |
|-------|------|------|
| <2% | ✅ 正常 | 直接使用80px过滤 |
| 2-5% | ✅ 可接受 | 直接使用80px过滤 |
| 5-10% | ⚠️ 偏高 | 检查数据来源，考虑分层 |
| >10% | ❌ 异常 | **必须**检查数据准备流程 |

## 🎯 不同场景的对比

### 场景1：纯Motion-guided (推荐过滤)

```
数据特点:
  - 全图motion检测 → Blob中心 → 160×160 ROI
  - 目标距离: 远 (100-500米)
  - 目标尺寸: 8-40px

过滤影响:
  保留: 98-99%
  过滤: 1-2%

结论: ✅ 必须过滤，影响极小
```

### 场景2：混合数据集 (分层处理)

```
数据构成:
  - 70% Motion-guided (远距离)
  - 30% 多样性数据集 (各种距离)

如果统一过滤80px:
  Motion部分: 保留99% ✅
  多样性部分: 保留60-80% ⚠️
  总体: 保留88-92%

结论: ⚠️ 需要分层处理，不能统一过滤
```

### 场景3：包含近距离数据 (不推荐过滤)

```
数据特点:
  - 包含近距离拍摄 (10-50米)
  - 目标尺寸: 40-120px
  - 用于学习型号多样性

如果统一过滤80px:
  保留: 60-70%
  过滤: 30-40%

结论: ❌ 损失太大，应该智能缩放而非过滤
```

## 💡 核心结论

### 对于您的问题

**"Motion-guided ROI严格过滤>80px，还剩多少张图片？"**

**答案：98-99%，即几乎不损失数据！**

### 关键理由

1. **Motion-guided的本质**
   - 检测的是**远距离**微小目标
   - ROI160中目标主要在8-40px范围
   - 超过80px的case本身就很少（异常值）

2. **过滤的是异常数据**
   - 过近距离的采集
   - ROI切片失误
   - 不符合实际应用场景的case

3. **训练-推理一致性**
   - 推理时Motion只会提取小目标ROI
   - 训练时也应该只包含小目标
   - 过滤掉的大目标在推理时根本不会出现
